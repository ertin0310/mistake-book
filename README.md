# 奶蛙爱学习 · 错题本 + 间隔重复复习系统

一个给**要反复刷题的人**用的错题本：把错题录进来，软件按记住的程度安排哪天再复习，到期了就排进当天的队列，做完给它一个自评，下一次的时间自动往后推。

它解决的是"错题抄了就再没翻开过"这件事——复习时间由系统排，不由人记，也不需要人自己列计划表。

服务端渲染的 Web 应用，Flask + SQLite，单机一个文件库，**零构建步骤**。

---

## 一、两条命令跑起来

需要先有 Python 3.10 以上（本项目在 **Python 3.12.10** 上验证）。

**Windows（PowerShell 或 cmd）**

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python run.py
```

**macOS / Linux**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

启动后打开 **http://127.0.0.1:5000** 。程序会自己建 `var/` 目录、自己建库建表、自己是空库时自动灌入演示数据，**不需要手工执行任何初始化命令**。

跑测试：

```bat
.venv\Scripts\python -m pytest
```

2026-10-23 在 Python 3.12.10 上实测：**406 条用例通过、1 条按环境跳过**（44 秒）。

## 三、环境变量怎么配（只写方法，仓库里没有值）

需要配置的只有会话签名密钥，而且**不配也能跑**。

| 变量 | 是否必需 | 不配会怎样 | 配置方法 |
| --- | --- | --- | --- |
| `SECRET_KEY` | 建议配 | 程序第一次启动时**自动生成一个随机密钥**存进 `var/.secret_key`，重启后继续有效，功能完全不受影响 | 复制 `.env.example` 为 `.env`，把值填进去。生成一条：`python -c "import secrets; print(secrets.token_urlsafe(32))"` |
| `AI_API_KEY` | **可留空** | 拍照识题的入口整块不出现，其余功能完全不依赖它 | 同上 |

两点说明：

- `.env` 已被 `.gitignore` 拦住，**仓库里只有 `.env.example` 这个模板，没有任何密钥值**。
- 想换掉自动生成的密钥、让所有人都重新登录，删掉 `var/.secret_key` 就行。
- `AI_API_KEY` 是给规划中的拍照识题预留的，**当前版本还没有接**，填了也不会出现入口。

## 四、哪些东西不进仓库

`var/` 目录整个被 `.gitignore` 拦住，里面有：SQLite 库文件、上传的题目图片、自动生成的会话密钥、启动时生成的样例数据文件。

所以 clone 下来的仓库里根本没有这个文件夹，靠程序启动时自己创建。**换机器就算代码跑起来了，你的错题数据也不会跟着过去——数据备份自理。**

侧边栏按模式分组：学习模式与复习模式各 5 条一级入口，其中「导入」可以展开成「手动录题 / CSV 录题」两条；首页、设置、申诉这三条收在**右上角用户名旁的倒三角**里；管理员再多一组「后台」，点进去是独立布局的后台页面。菜单只是导航，真正拦人的是路由上的登录/管理员装饰器和数据层的归属过滤。

| 功能 | 在哪里能看到 |
| --- | --- |
| 注册 / 登录 / 退出 | `/register`、`/login`，密码用 bcrypt 存哈希 |
| 登录后的《站点协议》门 | 登录后先看正文，同意记录入库；协议升版后会再弹一次；只能看当前生效版或自己同意过的版本 |
| 首页看板 | `/`：今日四个数（错题总数 / 今日待复习 / 今日已复习 / 今日新增错题）、掌握度四格、最容易错的知识点前五、一排快捷入口；有到期题时主按钮是"去复习今日到期" |
| 学习 / 复习双模式切换 | 顶栏两颗按钮，切过去只显示那一组菜单，并且**落到该模式的主页**（学习→我的题目，复习→今日复习） |
| 录入题目 | 「导入」→ 手动录题（默认落点），简答、选择、填空三种题型 |
| 题目列表与条件检索 | 「我的题目」按科目筛，全站统一翻页，每页 20 条 |
| 练习与自动入队 | 「刷我的题」：先作答再对答案，标记做错后这道题**当天就进今日复习**；选择/填空当场机器判分 |

| 申诉与反馈 | 右上角账户菜单 → 「申诉与反馈」：四类（题目有问题 / 判分有误 / 知识点申诉 / 其它反馈）提交后在同一页看处理状态与回复 |
| 管理后台 | 侧边栏「后台」→ 概览（待办数）、科目管理（新建 / 改名 / 停用，**没有删除按钮**）、知识点审核（通过 / 驳回带原因 / 下架 / 直建）、申诉队列（收尾必须写回复）、建库自检 |
| 建库自检 | `/admin/diagnostics`：19 张表逐张列行数、库文件路径、复习日切换时刻、AI 入口是否配置。**普通用户看不到这一页**（实测 403） |
| 设置 | 右上角账户菜单 → 「设置」：昵称、每日复习时间、每日复习量上限、默认模式、时区 |

## 七、一条必须写明的"日界"规则

复习按"复习日"排，不是按自然日。判断今天属于哪一天的入口是 `src/domain/clock.py` 的 `compute_review_date()`，全项目只有这一处，热力图、近 30 天趋势、"今日复习"都以它为准。

每个用户可以设一个"每日切换时刻"。**默认时刻是 `00:00`，此时"改了当天就生效"这条分支一次都不会走到**——因为"当前时间早于今天的 00:00"永远不成立，所以**没手动改过这个时刻的用户，改了设置一律第二天生效**。

这不是缺陷。这么定的理由是：如果晚上 8 点之后改时刻能立刻生效，"今天"会退化成"昨天"，**当天已经刷完的题会重新出现一遍**。只有在把默认时刻改成非 00:00 之后、且改的时刻还没到，才会当天生效。这条已由测试钉住（`tests/test_clock.py`）。

另外，时区下拉本期**只存值、不参与计算**，所有时间按服务器所在机器时间；时区留空或填了认不出来的值，一律回落本机时间。

## 十、AI 工具与模型使用说明

本项目全程用 **Qoder Desktop**（AI 编程 IDE，Agent 模式）协作完成，模型是 Claude 系列。题目允许 AI 辅助，这里如实写清**谁做了什么、AI 用在哪个环节、边界在哪儿**。

### 10.1 会话分工

按时间先后，同一个仓库上开过五条会话，各管一段，互不越界：

| 会话 | 阶段 | 负责什么 | 产出 |
| --- | --- | --- | --- |
| 分析考核题目任务二 | 选题（10-18，会话目录日期为证） | 读题目、定选题与技术栈 | 需求与选型结论 |
| 阅读题目与方案查问题 | 方案复核 | 逐条复核设计方案 | 会当场白屏的问题清单 |
| 审阅方案可行性 | 架构定稿 | 对账施工单、定分层与可见性原则 | 数据表与分层口径定稿 |
| 配合解题（施工主线） | 施工（10-21 起，即 `docs/提示词记录.md` 的 A-1 之后） | 按档写代码、跑测试、修 bug | `src/`、`tests/`、`docs/提示词记录.md` |
| 交付文档 | 收尾（10-23） | 只写 README 与项目说明书，不碰代码 | 本节所在的两份文档 |

施工主线与文档线是**两个会话并行**跑的：一个改代码，一个写交付文档，各自的文件写入权互不重叠（文档线只新建 `README.md` 和 `docs/项目说明书.md`）。

### 10.2 AI 用得最多的四个环节

- **设计对账**：把方案文档整份读进去，要求它按"会不会当场报错"排序逐条挑问题，而不是泛泛评价。
- **实现与排错**：报错原文整段粘回，要求先解释成因再改；改完必须重跑测试并给出实测数字。**记录里有"AI 说改好了但页面是崩的"这种情形**（A-52 最典型：全项目三百多条用例全绿，回收站页面却直接 500，原因是那个类不继承基类、属性名对不上，而库里没有软删错题时那条分支根本走不到；补了一条专门踩这条路径的用例）。A-42 是另一类：写视图层时被规则拦下，要求先把底下的 service 与 repo 层跑到绿才回头写页面。
- **复核自己的输出**：文档里每个数字都要求现跑现数（`pytest`、`grep`、只读方式连库查行数），不许引用记忆或对话里给过的数。这一条当场纠出过多处错，例如把首页说成建库自检页、把切换时刻"当日生效"的条件写成新时刻而不是原时刻、把提示词记录里的编号引串。
- **写交付文档**：需求分析、表设计、路由清单、算法取舍由 AI 起草，人逐节核对。

### 10.3 三条硬性边界（决定这些记录是真的）

1. **不越命令**：AI 不许自作主张加功能、改相邻机制或提前动手；每轮结束要停下等指令。违反过一次并完整回滚——把"缺的东西补一下"听成"把第 0 档缺的文件全写出来"，一口气生成 20 个文件，全过程与当时的报错原文记在 `docs/提示词记录.md` 的 A-3，随后的自查在 A-16。
2. **一步一演示**：每个阶段做完必须给出可粘贴的演示命令和"点哪里能看到"，演示不出就不算完成，不许往下走。
3. **决定权在人**：涉及权限、合规、要不要接外部 AI 这类取舍，AI 只列选项与利弊。项目曾就此反复两轮（先定为不接、后改为预留接口与配置位但功能本期不实现），这个反转与理由如实记在文档里，没有粉饰成一开始就想清楚了。

因此本仓库里的 AI 用法偏向"**能查错的手，不是拿主意的脑子**"：算法选型、表结构、权限模型、哪些功能本期不做，都是人拍的板；AI 负责把决定落成代码、把不一致的地方查出来、把过程如实记下来。

### 10.4 关于产品内的 AI

软件本身**没有调用任何 AI 接口**：拍照识题排在二期，`AI_API_KEY` 这个环境变量是给那条路预留的，留空不影响任何功能（见第三节）。
